# Pharmaceutical R&D valuation under regulatory uncertainty

Explore how development risk, investment decisions and regulation affect the value of a pharmaceutical R&D project. This notebook simulates a project through three development phases and estimate when continuing investment is preferable to abandoning it.

The analysis compares a base case with two regulatory changes: a shorter period of commercial protection and a reduction in annual net cash flow. Additional experiments examine sensitivity to economic assumptions, combinations of commercial terms with equal project value, and numerical precision.

## How the model works

1. **Simulate development.** Cash-flow estimates and remaining development costs fluctuate over time. A phase finishes when its remaining-cost process crosses zero. Technical failure can terminate the project.
2. **Value commercialization.** After phase III and an approval delay, the project earns protected commercial cash flows. At expiry, terminal value is five times the final annual cash flow.
3. **Estimate investment decisions.** Least Squares Monte Carlo fits continuation values using cash flow and remaining costs. Investment continues when predicted continuation value exceeds the next period's spending.
4. **Calculate project payoffs.** The model discounts commercial value and subtracts development costs incurred before completion, failure or abandonment.

All monetary values are **USD million**. Cash flows and spending rates are annual; time is measured in years. A reported project value is a discounted net value, not an annual cash flow.

## Base case and regulatory scenarios

The base case uses an initial annual cash-flow estimate of USD 20 million, a 4% discount rate, 15% annual commercial growth, 10 protected commercial years and a 1.5-year approval lag. Technical-failure probability is **0.0091 per month**. The notebook's commented parameter dictionary gives the remaining cost, spending and uncertainty assumptions.

- **Base case:** no regulatory event; technical failure and abandonment still apply.
- **Regulatory event I:** a 20% probability of reducing commercial protection from 10 to 8 years.
- **Regulatory event II:** a 20% probability of retaining 70% of commercial cash flows.

### Reusing saved Monte Carlo results

Each completed replication is saved to CSV. By default, `run_experiment` uses `resume=True`: it reads compatible saved results, skips completed replications and calculates only missing ones. If all requested replications are already saved, the cell displays their summaries without running new simulations. This also allows an interrupted experiment to resume from its last completed replication.

Before reusing results, the function checks model parameters, computational code and recorded software versions. If these differ, it stops and asks for a new output directory rather than combining incompatible runs.

To rerun the experiments while preserving existing results, change `OUTPUT` in Section 6.1 to a new folder before executing the experiment cells:

```python
OUTPUT = 'results/monte_carlo_new_run'
```

Alternatively, pass `resume=False` to a particular `run_experiment(...)` call to calculate that experiment again. **This replaces the shared checkpoint and configuration in that output folder**, so using a new folder is preferable when retaining earlier experiments. Subsequent experiment calls can use the default `resume=True` to accumulate compatible results in the new folder.

The first replication uses development and valuation seeds 42 and 50. Later seed pairs are generated reproducibly from their replication indices. Rerunning with unchanged settings and software should reproduce the same results; forcing a rerun does not select new random seeds. Small numerical differences may occur across platforms or numerical-library versions.

The replication experiments call the same `simulate_paths` and `valuation_procedure` functions as the main analysis and refit the investment policy in every run. They use the base case without regulatory events. Matching replication indices across path counts does not imply nested simulated paths.
